# 화면 전환과 댓글 배치 유지보수

## 현재 수정안

앱 전환 함수 `Ka.n.g/i/k/m`의 스프링(감쇠 비율 1.0, 강성 600, 위치 종료 기준 1px), 원래 이동 방향과 거리는 유지한다. Compose의 공용 `androidx.compose.animation.h.b(F0.M, F0.G, long)`에는 코드를 주입하지 않는다. 댓글을 포함한 다른 화면도 사용하는 측정·배치 계산은 원본 그대로 실행한다.

사용자 휴대폰 화면에서는 여러 줄 댓글이 작성 시간과 다음 댓글의 작성자·본문에 겹쳐 표시됐다. 0.3.5–0.3.7의 공용 측정 훅은 앱 전환에 한정되지 않았고, 기존 `v3` 값을 보존하거나 이후 사용을 확인하지 않은 채 `N/O` 필드 검사에 사용했다. 스크린샷만으로 정확한 발생 경로를 확정할 수는 없다. 수정안은 이 의심 경로 전체를 제거하고 원본 배치 계산을 복원한다. 남은 레지스터 하나를 임의로 골라 교체하지 않는다.

삭제한 `SlideLayer`와 전용 compile-only API 선언은 더 이상 사용하지 않는다. 광고 제어, 본문 준비·뷰 재사용, 미디어 저장 코드에는 변경이 없다. **본문 표시 최적화**를 끄는 것만으로 기존 공용 측정 훅이 해제되지는 않으며, 앱 재시작이나 설정 변경으로 설치된 패치 바이트코드를 되돌릴 수 없다.

## 검증 상태와 설치

이 수정안은 아직 릴리스하지 않았다. `patches-bundle.json`과 v0.3.7 릴리스는 변경하지 않아 기존 Morphe 소스에서 받는 번들에는 수정이 포함되지 않는다.

소스 비교로 공용 배치 훅과 그 전용 파일만 제거했고, 앱 전환 스프링 및 본문·광고·미디어 처리 코드는 유지했는지 확인한다. 작업 환경에는 JDK 21, Android SDK와 GitHub Packages 인증이 없고 Gradle 배포판 다운로드도 실패하여 번들 빌드는 완료하지 못했다. 원본 Plus APK와 Android 실행 환경이 없어 패치 적용·설치 및 화면 검증도 수행하지 못했다. 원인 확정이나 실기기 해결 완료로 표현하지 않는다.

빌드 가능한 환경에서 다음 명령으로 번들과 패치 목록을 생성한다. 자동 생성되는 `patches-list.json`은 직접 수정하지 않는다.

```sh
./gradlew :patches:buildAndroid generatePatchesList
```

빌드 후 이미 패치된 APK가 아닌 원본 Plus APK에 적용한다. 기존 Morphe 서명키를 유지한다. 원본의 `androidx.compose.animation.h.b`가 수정되지 않았는지 디스어셈블한 결과를 비교하고, 아래 화면 검증을 마친 뒤 새 버전과 번들 메타데이터를 배포한다.

1. 첨부 화면과 같은 글에서 짧은 댓글·여러 줄 댓글·이미지 댓글을 함께 표시하고 작성자, 시간, 다음 댓글 사이의 공간을 확인한다.
2. 댓글 끝까지 스크롤하고 되돌아오며, 답글 펼치기/접기와 새 댓글 로딩을 확인한다.
3. 글꼴 크기·화면 방향·테마를 바꾼 뒤 댓글 높이가 다시 계산되는지 확인한다.
4. 목록→글→뒤로 이동, 전환 중 빠른 뒤로 이동, 이미지 확대와 복귀를 확인한다.
5. 본문 표시 최적화를 각각 켜고 끈 상태에서 두 글 이상을 번갈아 열고, 앱 배경 진입·복귀를 확인한다.

## 이전 레이어 최적화의 측정 기록

0.3.5–0.3.7은 크기 애니메이션 `N`과 정렬 위치 애니메이션 `O`가 없는 경우 슬라이드 상태 읽기를 측정 단계에서 그래픽 레이어로 옮겼다. 이 경로는 현재 수정안에서 제거했다.

이전 Android 15 / 120Hz 에뮬레이터에서 동일한 강성 600/종료 기준 1px으로 설정→다운로드 큐→뒤로 가기를 6회 반복했다. 원본 측정 경로는 883프레임 중 지연 21회(2.38%), 레이어 경로는 881프레임 중 24회(2.72%)였다. 따라서 제거한 최적화의 프레임 지연 감소는 입증되지 않았다. 기존 CPU 비교는 당시 전체 번들에 대한 결과이며 이번 수정안의 성능 측정으로 사용하지 않는다.

## 앱 업데이트 시 확인

`Ka.n`의 네 메서드, 원래 tween 호출, 레지스터 수와 이동 방향 함수가 여전히 일치하는지 확인한다. 현재 앵커나 검사 조건이 달라지면 패치 적용을 중단한다. 새 버전의 의미를 확인하지 않은 채 검사만 느슨하게 하지 않는다. 버전 제한이 없는 대상도 실험용이며 향후 모든 버전의 호환성을 보장하지 않는다.
