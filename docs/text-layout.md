# 텍스트 겹침과 높이 캐시 호환성

## 0.3.15 변경

0.3.14 이후에도 증상이 남아 무조건적인 intrinsic 높이 재계산은 철회하고 0.3.10의 글꼴/줄 방향 기반 무효화로 복원했다. 최소 줄 높이의 fontScale 검사는 유지한다. 별도 본문 스크롤 위치 후보 보정은 [body-position.md](body-position.md)에 기록한다. 아래 0.3.14 설명은 당시 구현 기록이다.

## 0.3.14 추정 원인에 대한 추가 보정

사용자가 기존 보정 이후 겹침 빈도는 줄었지만 간헐적으로 남는다고 보고했다. 요청에 따라 재현 테스트를 중지했다. 아래 변경이 실제 기기의 원인을 해결했는지는 확인하지 않았다.

- 최소 줄 높이 계산기의 노드별·전역 재사용 경로에서 화면 밀도뿐 아니라 글꼴 크기 배율도 비교한다. 원본은 글꼴 배율을 비교하지 않아 배율이 다른 계산기를 재사용할 수 있었다.
- 기존 **댓글·본문 글자 높이 보정**이 켜져 있으면 별도의 너비→intrinsic 높이 캐시는 재사용하지 않고 측정 요청에서 다시 계산한다. 이전 intrinsic 측정값을 가져오는 가능성을 보수적으로 제거한다. 완성된 문단·레이아웃 캐시와 그리기 경로는 유지한다.
- 옵션을 끄고 앱을 재실행하면 위 두 보정도 해제된다. 글자 높이 측정 비용이 증가할 수 있으며 CPU·배터리 절약을 주장하지 않는다.

현재 증상에 대한 후보 수정이며 해결 확정판이 아니다. 사용자 요청으로 이 변경 이후 에뮬레이터 실행·스크롤 검증을 하지 않는다. 빌드와 원본 APK에 대한 패치 적용 검사는 별도로 기록한다.

**v0.3.8은 실행 불가 보고로 사용 중단했다.** v0.3.9는 아래 텍스트 캐시 패치·추가 필드·설정 옵션을 모두 제거하고 v0.3.7의 앱 패치와 확장 소스로 복원한다. 정확한 실행 오류 로그는 확보하지 못했다. 아래 내용은 철회한 구현의 유지보수 기록이며, 현재 기능이나 검증된 해결 방법이 아니다. 댓글 겹침 문제는 미해결 상태다.

## 보고된 문제와 확인 범위

2026-10-13 사용자는 v0.3.7에서 여러 줄 댓글이 작성 시간과 다음 댓글까지 겹친다고 보고했다. 앱 재실행과 저장 캐시 삭제 후에도 동일했다. 댓글의 일반 텍스트와 HTML 텍스트는 `w9.B.n`에서 `X8.k.m/n`과 Compose의 텍스트 노드를 거쳐 표시되며 본문 WebView와 별도 경로다.

사진의 직접 원인을 기기에서 재현한 것은 아니다. 기존의 테스트 생략 요청을 유지해 에뮬레이터·휴대폰 회귀 테스트와 CPU·배터리 측정은 수행하지 않았다. 이 변경을 사진 속 문제의 검증된 해결이라고 표시하면 안 된다.

## 코드에서 발견한 갱신 누락

기준 Plus APK의 `N.e.d(width, direction)`과 `N.f.f(width, direction)`는 이전 너비가 같으면 저장한 텍스트 높이를 반환한다. 이 반환 경로는 줄 방향과 해석된 글꼴의 stale 상태를 확인하지 않는다. 또한 글꼴 intrinsics를 재생성하는 `N.e.l`과 `N.f.n`에는 저장한 높이와 최소 줄 수 계산기의 무효화가 없다. 특히 `N.f`는 intrinsics가 먼저 갱신되면 실제 paragraph는 이전 글꼴인데도 동일 제약에서 재사용할 수 있다.

이는 AndroidX가 수정한 [stale font intrinsics cache 문제](https://android.googlesource.com/platform/frameworks/support/+/9a10a4c5bf8507c1f4128fdb2b0b3953a4ab535b)와 같은 코드상 누락이다. 앱에서 이 경로가 사용자의 사진을 유발했는지는 별도 확인이 필요하다.

v0.3.8은 위 정책을 기준 APK의 API에 맞춰 보완한다.

- 높이 재사용 전에 줄 방향과 글꼴 stale 상태를 확인한다.
- intrinsics를 재생성하면 이전 높이·너비와 최소 줄 수 계산기를 무효화한다.
- 기존 intrinsics가 교체되면 다음 실제 측정에서 paragraph를 새로 생성한다. 기존 layout 객체는 측정 전까지 보존해 draw 중 접근을 깨뜨리지 않는다.
- 앱의 구형 최소 줄 수 계산기는 전역 최근 객체도 재사용하므로, 기존 intrinsics 교체 시 그 전역 참조도 해제한다.
- 측정을 완료하거나 원래 캐시가 reset되면 새 stale 표시를 해제한다.

기존 줄바꿈·글자 크기·내용·링크 처리·줄 수 제한·크기 제약을 유지한다. 강제 여백, 고정 높이, 글자 자르기, 폰트 교체, 주기적인 재측정이나 프레임 루프를 추가하지 않는다. 공유 Compose 텍스트 캐시를 고치므로 댓글 외 텍스트에도 적용된다. 기존 스프링·슬라이드 레이어와 본문 최적화는 변경하지 않는다. 안정된 높이와 글꼴은 계속 재사용하지만 이 보완의 CPU 또는 배터리 효과는 측정하지 않았다.

## 앱 내 설정과 업데이트

설정 → Morphe 설정 → 텍스트 표시 → **텍스트 높이 호환성 개선**에서 선택한다. 기본값은 켜짐이다. 선택한 값은 저장되며 정책은 새 앱 프로세스 시작 때 읽는다. 옵션 변경 후 앱을 완전히 종료하고 다시 실행해야 한다. 설정 화면은 저장된 선택을 표시하고, 측정 경로는 메모리에 보관한 값을 읽는다.

앱 업데이트 때 `TextLayoutCompatPatch.kt`의 두 클래스에 있는 필드 의미, height/intrinsics/reuse/reset/measurement 메서드의 레지스터와 분기, `O0.l/t.b()`의 stale-font 의미, `N.c.b()`의 공유 계산기 setter를 확인한다. 미일치 시 패치를 중단한다. 다음에는 해당 글의 여러 줄 댓글, 큰 글꼴·기본 글꼴, 테마 변경, 스크롤·복귀·뒤로 가기, 링크 클릭, 옵션 양쪽을 확인해야 한다.

## 0.3.10 현재 시험 구현 (2026-10-27)

0.3.8의 삽입 분기는 라벨 위치가 잘못 연결되어 `move-result`로 되돌아가는 문제를 만들었다. 별도 Android 15 에뮬레이터에서 ANR을 확보했고, 새 빌드의 검증 오류 로그와 실제 DEX에서도 잘못된 분기를 확인했다. 분기 삽입을 `addInstructionsWithLabels`로 수정했다. 이전의 sticky boolean dirty 필드도 복원하지 않았다.

현재는 완료된 layout이 사용한 intrinsics 객체를 별도 참조로 보관하고, 현재 intrinsics가 다르면 다시 측정한다. 너비만으로 높이를 재사용하기 전에 글꼴 stale/줄 방향을 확인하며, 새 intrinsics를 만들 때 높이와 최소 줄 수 계산기를 무효화한다. 실제 측정이 완료되면 새 참조를 기록한다. 그리기 객체를 도중에 null로 만들지 않는다.

Morphe 설정의 **댓글·본문 글자 높이 보정**은 기본 켜짐이고 앱 재실행 때 정책을 적용한다. 에뮬레이터에서 시작, 채널/게시글 로딩, 텍스트·이미지 댓글의 빠른 왕복 스크롤, 기본/1.4배 글자 크기를 확인했다. 관찰 화면은 겹치지 않았고 크래시 로그도 없었다. 기존 0.3.9에서 사용자와 같은 간헐적 겹침을 재현한 것은 아니므로 실제 기기 해결 여부는 별도 확인이 필요하다. 0.3.8은 계속 철회 상태다.
