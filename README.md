# Arca Live personal Morphe patches

This repository contains experimental [Morphe](https://github.com/MorpheApp/morphe-patcher) patches for **Arca Live Plus** (`live.arca.android`). It contains patch source only, not the vendor APK, decompiled application, signing keys, or account data. It is not affiliated with Arca Live or Morphe.

## Patches

- **Morphe 설정·광고·스프링 전환:** Adds a separate **설정 → Morphe 설정** page with runtime controls for app-owned ads and article-view reuse. The ad switch controls the app-owned `/api/v1/pagead` request and its `¡Hola!` slot. The separate user text-ad API, posts, comments and linked images remain available. User-created advertisements in posts are untouched. When the ad switch is off, the original ad slot returns. App-owned ad requests read a cached switch rather than preferences from disk each time. Article-view reuse reduces repeated body setup and is described in the [article rendering notes](docs/article-rendering.md). The four shared Compose navigation transitions retain the vendor's left/right directions and travel distances; their 250 ms tween is replaced by a critically damped spring (damping ratio 1.0, stiffness 600, 1-pixel IntOffset visibility threshold). Pure slides read their animated position in the existing graphics layer rather than the measurement pass, avoiding measurement invalidations caused by that position. Transitions with size or alignment animation retain the original path. There are no animation controls, extra frame loops, forced refresh rates, or changes to Activity animation resources. See [rendering and maintenance notes](docs/rendering.md).
- **분석 수집·백그라운드 작업 축소:** Sets Firebase Analytics, Crashlytics and Sessions collection flags to false, disables analytics-only measurement and session services/jobs, and removes advertising-ID and install-referrer permissions. Firebase Messaging and Remote Config remain for notifications and app settings. This avoids those background entry points but does not establish that every possible telemetry request is gone or quantify battery savings.
- **미디어 저장 스트리밍:** Marks the media download endpoint as streaming and copies its response to the Android media file using a 64 KiB buffer. The Android 10+ save path is shared by image, GIF and video download items; the original path loaded the complete response as a byte array before writing it. The legacy Android saver already streams. The copy now closes both streams even if writing fails. This reduces peak memory use and avoids waiting for Retrofit's full-body buffer before writing. It does not alter playback, previews, or the serial download queue; network and server limits can still dominate elapsed time.

The verified baseline is **Plus 0.9.32768** (`versionCode 122768`, original APK SHA-256 `0EBA2DCB598B9F3AB6720266DF1E4E822D3A9522AED43479F79AE3C8BA2E0AB4`, publisher signing certificate SHA-1 `D7F68DAD9E0C02DCF5A4167BE13E86B5E68696B5`). Later versions are marked experimental and each required class/method anchor is checked at patch time. Review and test every app update before use.

## Build and install

The [Morphe Gradle setup](https://github.com/MorpheApp/morphe-patcher/blob/main/docs/2_1_setup.md) requires JDK 21, Android SDK and GitHub Packages authentication with `read:packages`.

```sh
./gradlew :patches:buildAndroid generatePatchesList
```

The resulting bundle is `patches/build/libs/patches-0.3.7.mpp`. In Morphe Manager, add `https://github.com/Lumi-01/arca-personal-patches` as a [patch source](https://github.com/MorpheApp/morphe-manager/blob/main/docs/patch-sources.md) and patch your own copy of the app. The [v0.3.7 release](https://github.com/Lumi-01/arca-personal-patches/releases/tag/v0.3.7) supplies the bundle directly. Morphe's signature differs from the publisher's, so installing over the stock app may require backing up local data and uninstalling it first. Keep the same Morphe signing key for future patched updates.

When publishing a new `patches-bundle.json`, keep `created_at` in Morphe's local date-time format (`YYYY-MM-DDTHH:mm:ss`, without `Z` or an offset). Morphe Manager 1.34.0 cannot parse a UTC suffix in this field and then reports that the bundle could not be downloaded.

## Verification and limits

Version 0.3.7 removes duplicate DOM-to-HTML serialization: the original final selection serialized the same body twice and eagerly built an unused expand-images button; it now serializes once and builds the original button only when selected. This safe calculation reduction is always applied. With **본문 표시 최적화** on, empty content without votes bypasses DOM preparation, while nonempty HTML is prepared by one finite background worker owned by the original Compose remember group. Work is cancelled when that group is forgotten or abandoned, queued cancelled tasks are removed, and the worker retires after 10 seconds idle. No network prefetch, polling or extra frame loop is added. Native body-view construction follows the original first-resume signal; a body already shown remains present during exit motion. The option restores synchronous preparation and original view-construction timing for subsequent articles when off. The duplicated serialization fix retains the original theme, image-folding, iframe and vote paths; local diagnostic builds produced matching output lengths and hashes for 20 fixed-input cases covering both themes and data-saver states. The diagnostics are excluded from the published bundle. See [CPU measurements and limits](docs/article-rendering.md). Emulator frame results remain variable and do not establish that phone stutter is solved or quantify whole-app CPU or battery savings.

Version 0.3.6 adds **본문 표시 최적화** in Morphe settings. It keeps at most one paused, empty article WebView for reuse in the same foreground Activity and exact Context, binds fresh callbacks for the new article, and releases the cached view on Activity pause/destruction, configuration change or memory pressure. Cookies and shared HTTP caches are preserved; no article is prefetched and no hidden WebView is created at startup. HTML loading follows the app's existing resumed-state signal, separating page rendering from navigation while the entry is paused. Turning the option off restores fresh-view creation and the original HTML loading timing. It has a small bounded memory cost, and the first provider initialization still occurs normally. See [article rendering, measurements and maintenance](docs/article-rendering.md). In a short 120 Hz emulator comparison, repeated factory setup fell from 9.6–15.3 ms to 0.6–1.4 ms and the worst frame per entry from 49–58 ms to 34–42 ms. These are three warm entries per mode, not a phone benchmark or a guarantee of smoothness. Phone smoothness and battery savings remain unmeasured.

Morphe Desktop 1.18.1 applied the three default patches to the Plus baseline. On an Android 15 x86_64 emulator, Plus opened a channel and post, kept the text-ad row, removed the `¡Hola!` area without a blank gap, and saved a 123 KB image into `Pictures/ArcaLive`. The Morphe settings page opened without clipping and shows no animation controls. A screen recording with Android's animator duration scale set to 1.0 shows the patched app sliding in the original left/right directions on both channel and post navigation. Earlier emulator recordings appeared to show no animation because that AVD's animator duration scale was 0. The user reported the missing animation and stutter on a real phone; that phone's animation settings and the spring's appearance there have not been verified. Article content can still have a short blank/loading period before network data arrives. Login, posting, push delivery, other Android releases, batch download speed and real-device battery impact have not been verified. The source could still change between app releases, and this patch does not guarantee a speed increase or a measurable battery improvement.

The user reported worse stutter with v0.3.4 on a 120 Hz phone. That version shortened the motion with stiffness 1200; its lower frame count on a 60 Hz emulator did not establish a reduction in work per frame. Version 0.3.5 restores stiffness 600 and defers slide-state reads to the graphics layer. The test AVD was cold-booted with `hw.lcd.vsync=120` and host GPU rendering; Android reported a 120 Hz active render rate and 8,333,333 ns frame intervals. A recording and UI checks confirm settings/download navigation, the original slide geometry, channel/post loading and back navigation. Physical-phone smoothness and battery savings remain unmeasured.

The Java-only injected extension previously bundled unused Kotlin runtime and annotation classes. Excluding them reduced its DEX from about 2.28 MB / 1,128 classes to a small Java-only DEX. This is a size and class-loading reduction, not proof of a frame-rate gain. On a connected Android 17 phone running Plus 0.9.32768, Android reported the installed app's dex optimization as `verify`. After `adb shell cmd package compile -m speed -f live.arca.android` and an app restart, observed janky frames fell from 125/944 (13.2%) to 42/1041 (4.0%) in user-driven channel/post navigation, with a small subjective improvement. The runs were not identical, so this is diagnostic evidence rather than a guaranteed result. The command is optional, requires ADB access, and Android may reset compilation after an app update. The original app already bundles AndroidX ProfileInstaller and a baseline profile; a patched Plus build logged `RESULT_INSTALL_SUCCESS` on an Android 15 emulator, so `verify` alone does not show that its profile installer failed.

The patches target app-owned requests. Embedded web content or user-provided links may still make their own network requests.
